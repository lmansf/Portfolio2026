      How the run works

      1. Extract. Rebuild the site’s tables from its own pages, read the fraud pipeline’s published snapshot, and pull public activity from the GitHub API. A source that can’t be reached keeps its last good data and fails its freshness check here.
      2. Test. Hold every table to the tests written down once, check every column is described, and rerun each “SQL source” query to prove it still returns what its page shows. The data catalog lists every table, column and metric those tests cover.
      3. Log. A scheduled GitHub Action commits the results, the site redeploys, and this page reads them.
