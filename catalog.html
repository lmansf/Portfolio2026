Metrics

each is also a SQL macro

  • Catch rate catch_rate(fraud_caught, fraud)

    Share of fraudulent orders the rules flagged (sent to review or declined). fraud_caught / fraud, on fraud_totals, fraud_daily, fraud_patterns as caught / fraud.

    Home and Projects quote it as “flagged about half the fraud”; the nightly run checks it stays 40% to 60%.

  • Fraud approved miss_rate(fraud, fraud_caught)

    Share of fraudulent orders the rules approved: the fraud that got through. (fraud - fraud_caught) / fraud, on fraud_totals, fraud_daily, fraud_patterns as (fraud - caught) / fraud.

  • Good customers declined false_decline_rate(false_declines, legit)

    Share of legitimate orders the rules declined outright. false_declines / legit, on fraud_totals.

  • Good customers flagged legit_flag_rate(flagged, fraud_caught, legit)

    Share of legitimate orders the rules sent to review or declined. (flagged - fraud_caught) / legit, on fraud_totals.

    Home and Projects quote it as “and no legitimate orders”; the nightly run checks it stays 0%.

  • Fraud dollars stopped dollars_stopped_share(fraud_dollars_stopped, fraud_dollars_approved)

    Share of attempted fraud dollars on orders the rules flagged. fraud_dollars_stopped / (fraud_dollars_stopped + fraud_dollars_approved), on fraud_totals, fraud_daily.

  • Fraud rate fraud_rate(fraud, checkouts)

    Share of all checkouts that were fraudulent. fraud / checkouts, on fraud_totals, fraud_daily.

  • Scoring timeouts timeout_rate(scoring_timeouts, checkouts)

    Share of checkouts whose fraud score timed out and failed open (approved unscored). scoring_timeouts / checkouts, on fraud_totals.

Sources and staging

  • raw Page markup

    The Home and Projects pages as published. They are the source of truth for the site's own tables, so a table can never say something the pages don't.

    index.html, projects.html

  • staging Parsed page rows

    Each card, role, skill, credential and the hero, read out of the page markup into typed rows (dates parsed, badges split from titles).

    scripts/build_console_data.py

  • raw Supabase checkout tables

    The fraud pipeline's four raw Postgres tables of simulated webstore checkouts. They stay in Supabase: nothing row-level ever reaches this site.

    raw_transactions, raw_fraud_decisions, raw_fraud_truth, raw_checkout_responses

  • staging Scored checkouts, last 30 days

    One row per scored checkout in the last 30 America/New_York days, joined to the generator's answer key. Built inside a read-only transaction on Supabase; only the aggregates below leave it, as data/fraud-snapshot.json.

    the base CTE in scripts/fraud-snapshot.sql

  • raw GitHub public API

    Public activity and public repositories for github.com/lmansf. Private work never appears here.

    api.github.com /users/lmansf/events/public and /users/lmansf/repos

  • staging Public GitHub events

    One row per public event in the last 30 days, keeping only its id, type, repository and time (no commit messages, names or emails).

    data/pipeline/stg_github_events.json, written by scripts/data_run.py
