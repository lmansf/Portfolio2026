# Portfolio2026 — working notes

Static HTML/CSS/JS portfolio (no build step), deployed on Vercel. Routing is in
`vercel.json`; design tokens in `assets/tokens.css` (the "Pipeline" style: rounded
panels, 1px hairlines, soft shadows, Schibsted Grotesk + JetBrains Mono, one
teal accent with amber/slate pipeline lane colors, Day + Night themes, no brown);
minified `.min` assets are what the pages load, so regenerate them after
editing source (esbuild is fine:
`npx esbuild <src> --minify --outfile=<min> --allow-overwrite`).

Text colors must stay WCAG AA on every surface token: the ink tokens and
`--accent-ink` pass; in Night `--accent` is a bright teal fill with dark
`--on-accent` text on it.

The Home hero animation (`assets/hero-pipeline.js`, loaded as
`hero-pipeline.min.js`) is progressive enhancement: the `[data-hero-pipe]` stage
is `hidden` in the HTML and the real `<h1>` stays the heading; the script
unhides the stage and adds `hero--pipe` (which visually hides the h1 text)
only once it can draw. Dots flow through three lanes, gather into an owl,
then settle into the name. Under `prefers-reduced-motion` it draws the final
name with no motion. After editing it, regenerate the `.min.js`.

Motion extras (the walking Owl Park owl, scroll reveals, button hover/press,
the copy-email button, `data-countup` numbers and the `/live` freshness dot)
live only in `assets/motion.js` and `assets/motion.css` (the script loads the stylesheet
itself, never as an inline `<style>`, which a strict CSP would block), so a
page opts in with one deferred script tag; `pages.css` is untouched and `shell.css` only carries
the `@view-transition` opt-in (it must be render-blocking to work). Keep the owl
in its reserved lane above the footer (it must never cover content or
buttons), keep every animation off or static under `prefers-reduced-motion`,
and leave the "Hide owl" choice in localStorage working.

The three featured project synopses (Quack Query, Fraud Detection Pipeline,
Owl Park) are the same text on Home and `/projects` and stay at about two
short lines each; the detail lives in the "How the data flows" diagrams.
Their markup exists once, in the fallback section at the end of
`projects.html`'s `<main>`: `assets/pipeline.js` opens each diagram in a
modal `<dialog>` from the card's "How the data flows" link (Home fetches the
figure from `/projects.html`), hides the section, and leaves the plain links
and section for no-JS and browsers without `<dialog>`. Keep each link's
`data-flow-open` equal to its figure id, keep the modal keyboard- and
reduced-motion-safe, and edit the diagrams only in `projects.html`. See the
README's "Site structure" and "Assets" sections.

The docked SQL console and `/playground` are retired (`/playground`
redirects to Home). In their place, each data-backed piece on Home,
Projects and `/live` has a collapsed "SQL source" caption (`.sql-src` in
`pages.css`, a native `<details>`) generated by
`scripts/build_sql_sources.py` between `<!-- sql-source: name -->` markers:
never hand-edit inside a marker pair. The caption holds the piece's default
query (`data/sql-sources/<name>.sql`), and `assets/sql-source.js` (bundled
with `sql-engine.js` into `sql-source.min.js` with `esbuild --bundle
--format=esm --minify`) turns it into an editor: Run loads DuckDB-Wasm on
demand and redraws the `[data-sql-piece="name"]` element from the result,
and Reset puts the page back. The page HTML must stay the default query's
output: Home and Projects queries run over `data/console/site.sql` (which
`scripts/build_console_data.py` generates from `index.html` and
`projects.html`) and `/live` queries over the `fraud_*` tables in
`data/console/snapshot-tables.json`; the captions script runs each one in
DuckDB (`pip install duckdb==1.5.6`) and fails unless it returns exactly
what the piece shows, so Home's featured cards must keep the same title,
eyebrow, year, synopsis and tags as their `/projects` cards. A broken or
odd query must never blank a piece (it shows a message or a small table
instead), text goes in only through `textContent`, and the hidden
`nest_box` hunt table stays queryable from every editor, with its clue in
the toolkit's default query and its name kept out of error hints. After
changing card, timeline, toolkit, credential, hero, "now" strip,
contact-button or footer copy, or the snapshot query, rerun
`build_console_data.py` then `build_sql_sources.py`; the `Console data`
workflow runs both `--check`s in CI and fails if `sql-source.min.js` is
stale. See the README's "SQL source captions".

Search/share metadata (head tags, JSON-LD, `sitemap.xml`, `robots.txt`,
`llms.txt`, `assets/share-card.jpg`, the favicon set) is documented in the README's "Search and
sharing metadata" section. When a page's head or facts change, bump that
page's `<lastmod>` in `sitemap.xml` and keep `llms.txt` and the Person
JSON-LD consistent with each other and with the résumé. The icon set
(`favicon.ico` at the root, `assets/favicon.svg`, the apple-touch and
manifest PNGs) and `assets/share-card.jpg` are generated by
`scripts/build_brand_images.py`, not hand-edited: rerun it to change them,
and keep the pages' `og:image:width` / `height` / `alt` tags in step with
the card (see the README's "Assets" section).

The résumé (`assets/loganmansfield.pdf` and `assets/resume_ats.txt`) is
generated, not hand-edited: change `resume-src/resume.md` and run
`python3 resume-src/build.py` (reportlab + Carlito; see the README's
"Assets" section). It must stay one Letter page. Content rules: the B.S.
Biology (Towson, 2019) is hidden for now at Logan's request (restore steps in
the README's "Hidden for now" section); no sticky-navigation claim; no dbt, CRM ownership, UAT, or
M365/D365 admin; titles and dates unchanged; LinkedIn is `in/lmansf96`.

The nest-box hunt (README, "The nest-box hunt"; contract in
`docs/egg-codes.md`) runs from the SQL source editors: keep
`api/egg/verify.js` and `api/egg/claim.js` working (Owl Park calls verify),
keep the shard order in `data/console/extra.sql` in step with the Owl Park
products' list prices in `data/playground/`, and never put `EGG_CODE_SECRET`
in the repo; it lives only in Vercel's environment variables.

The `/live` page (`live.html`, `assets/live.*`) is fed by
`data/fraud-snapshot.json`, which the `fraud-snapshot` GitHub Action
regenerates daily from `scripts/fraud-snapshot.sql` and commits to `main`.
Keep the SQL output, the workflow's `jq` allow-list, `live.js`, and the
`/live` SQL source captions (rerun `scripts/build_sql_sources.py`) in step
when fields change (`motion.js` also reads `generated_at` and
`latest_event_at` for the freshness dot on Home and Projects); the snapshot
holds aggregates only and the page must never carry a database key. See the
README's "Live fraud data" section.

The nightly data run (README, "The nightly data run") is
`scripts/data_run.py`, driven by `data/pipeline/models.json` (nodes, column
descriptions, tests, and the tables each caption reads) and the `Data run`
workflow; `/status` draws its `data/pipeline/run-log.json`. When a site
table or snapshot field gains or loses a column, describe it in
`models.json` (an undescribed column fails a check). Every SQL source
caption needs a `pieces` entry. Keep the hunt table out of `models.json`,
`/status` and anything else that lists tables. `run-log.json`, `github.json`
and `stg_github_events.json` are written by the run: don't hand-edit them.

Every rate the site shows is defined once in `data/pipeline/metrics.json`
(README, "Metrics"). `live.js` computes rates only through `metric()` in
`assets/metrics.js` (never its own division), and `live.min.js` is an esbuild
`--bundle --format=iife` build, not a plain minify. After changing
`metrics.json`, rerun `scripts/build_metrics.py` (it writes
`data/pipeline/metrics.sql`). If you change site copy that states a number
(like "flagged about half the fraud"), update its `claims` entry, or the data
run will say the copy and the number disagree.

`catalog.html` (`/catalog`) is generated by `scripts/build_catalog.py` from
`models.json` and `metrics.json`: rerun it after changing either, and edit
only the hero outside its `<!-- catalog -->` block.

## Validate portfolio PRs through the `no-mistakes` gate

Before opening a pull request for this portfolio, validate the change with the
`no-mistakes` skill (invoke `/no-mistakes`). It runs review → test → lint → docs
locally using the `claude` agent, on a committed feature branch.

Setup is handled automatically by the SessionStart hook
(`.claude/scripts/setup-no-mistakes.sh`); run it manually if needed:

    bash .claude/scripts/setup-no-mistakes.sh

### Environment caveats (Claude Code on the web)
- The container is ephemeral, so the `no-mistakes` CLI is reinstalled each
  session by the setup script (a Go build — a few minutes on first run).
- `gh` is **not** available here, so the gate's push / PR / CI steps cannot run
  in-session. Use `/no-mistakes` for the local validation steps, then open the
  PR through the normal GitHub flow (the `github` MCP tools), as we do today.
